# Printemps 设计原则

lint 查不出来的那一半规则。`pnpm lint:design` 能抓到写死的颜色、不在刻度上的字号和圆角；它看不出一个页面用了三层嵌套的盒子、每张卡都长出了边框、或者一屏出现了两个 primary。本页就是那半份检查，写给用设计稿实现界面的人或代理。每条规则都是一句可以直接说“不”的话，旁边写着原因。

Token 在 `src/renderer/tokens.css`（颜色、字号、圆角、间距、时长）。本页讲的是怎么用它们。参考渲染是 `design/Printemps.pen` 的画板与 `design/exports/*.png`：改任何东西之前，先打开最接近的画板对照。

## 1. 容器与边

- **盒子只在有结构或功能作用时才存在。** 先用留白和对齐分组。给每个元素都包一张卡，是生成式界面最容易被认出来的毛病。
- **分隔两个平面只用一种线索。** 一条 hairline（`--hairline`），或一次底色变化，或一层阴影——同一条边上不叠加。卡片用 1px `--hairline` 或底色变化其一，不再加阴影。
- **卡里不套卡。** 卡内的凹陷区用 `--field` 底色，不加描边、不加阴影（对话框里的列表、来源信息条都是这种）。
- **分隔线只用在互不相关的顶级区块之间。** 同组兄弟元素之间靠间距分隔；已经靠位置区分的兄弟之间再加线是噪音。
- **一张卡里只有一个“抬起来”的东西。** 卡本身就是那一层；卡内的按钮最多有接触阴影。
- **卡与浮层是同一平面。** 区别在于浮层有 `--scrim` 背景和更深的底色（`--overlay`），不在于描边。

## 2. 深度

- **只有两级：** 平铺（页面、卡、轨道头）和浮起（菜单、弹窗、下拉）。没有第三级、没有叠加阴影、内容层没有玻璃/模糊。
- **深度是相对于主题的。** 深色下，卡比板子只深一点，这点差异就是深度。不要为了“让卡看得见”而加边框——先检查底色 token。

## 3. 层级

- **一屏一个 accent。** 一个 primary 按钮、一种蓝。第二重要的操作用 secondary，绝不是第二个 primary。列表里每行各有一个 primary（如模型管理的“下载”）时，同一行仍只有一个。
- **操作区右对齐，primary 在最右，secondary 在其左。** 弹窗、卡片、通知条一律如此（2026-09-20 用户定稿）。
- **一屏最多三档字号。** 从 `--text-*` 里选。觉得需要第四档，是层级错了，不是刻度少了。
- **先用颜色，再用字重，最后才用字号来降级。** 想弱化：先 `--text-muted`，再更轻的字重，再更小的字号。不要三样一起上。
- **DAW 比例。** 页面标题 `--text-3xl`（22px），弹窗标题 `--text-2xl`（20px），首页大标题 `--text-display`（30px），常驻标签 `--text-xs`/`--text-sm`。参考 Logic/Ableton：没有 28px 以上的常驻文字。

## 4. 空间与密度

- **间距是刻度，不是数字。** 只用 `--space-*`（4 / 8 / 12 / 16 / 20 / 24 / 32 / 40）。同级兄弟等间距。13px 的间距意味着少了一档——说出来，不要写死。
- **内容靠上。** 不要把一块内容垂直居中在面板里；只有单个控件或空状态可以居中。
- **密度来自外壳，不来自组件。** 组件不猜自己在紧凑还是宽松布局里；1440×900 与 1280×800 由容器查询/媒体查询在外层决定。
- **容器内边距统一。** 想让某个子元素偏一点，用包一层的方式，不要给它单独的 margin。

## 5. 颜色

- **中性色承载界面。** `--bg`…`--raised-hover` 与文字 token 占每屏 95%。色相只出现在三处：accent（`--accent*`）、状态色（`--good`/`--warn`/`--danger`、`--solo`/`--mute`）、数据色（音轨/声部颜色，来自 `src/shared/stems.ts`）。其它地方不着色。
- **状态色表达状态。** `--good` 是“成功/就绪”，不是“这里绿色好看”。没有含义的颜色是装饰，装饰要删。
- **不要用字符串拼颜色。** 不写 `${color}66`、不在 JS 里调亮。用 `color-mix(in srgb, var(--token) X%, transparent)` 或新 token。
- **数据色只由音轨颜色驱动。** 波形、剪辑边框、剪辑标题、起始位置数值用 `--clip-color`/`track.color`；界面 chrome 不借用数据色。

## 6. 装饰

- **渐变、模糊、发光默认不用。** 唯一的渐变是 Printemps 品牌字标。
- **圆角来自表格**（`sm` 3 / `md` 8 / `lg` 10 / `xl` 12 / `2xl` 16 / `pill`）。8px 几乎是一切；复选框 `sm`；弹窗 `2xl`。不存在 5px、7px、9px、14px、18px。
- **拿不准就减。** 更少的盒子、更少的 chrome、更多的空间。不要为了“不那么模板化”而加特殊元素，去掉一个。

## 7. 动效

- **到达要缓，离开要快。** 用 `--dur-fast`（120ms，hover/按下）、`--dur-base`（200ms，选中滑块、分段控件）、`--dur-slow`（240ms，侧栏、面板展开）；曲线只用 `--ease-settle` 或 `ease-out`。不要发明新的 cubic-bezier。
- **动效解释状态变化，从不装饰。** 减少动态效果偏好下所有时长归零——token 已处理，不要绕过它。
- **一套词汇。** 新组件的进出与最近的现有浮层一致。

## 8. 先复用，后发明

- **组合，不重造。** 已有的 button / `.icon` / `.segments` / `.fader` / `.dialog` / `ErrorNotice` / `SaveRecovery` 拥有自己的内边距、颜色和形状；新界面通过 className 只做布局（宽度、边距），不改颜色/内边距/形状/字号。
- **顺序：** 现有组件 → 现有变体 → 在组件里加变体（写注释说明为什么） → 新组件。有现成表面时不要用裸 `div` 堆样式。
- **从最近的画板开始，不要从空白开始。** 复制结构，再改内容。
- **示例数据来自 `preview/main.ts`。** 不编数字、不写 lorem ipsum。

## Do / Don't

- ✅ 让留白分组，让对齐暗示结构。
- ✅ 一个 accent、一个抬起的表面、三档字号、两级深度。
- ✅ 改 token 前先读它旁边的注释。
- ✅ 中文 1440×900、1280×800、英文长文案三种状态截图对照后再算完成。
- ❌ 卡不加边框，卡里不套卡，兄弟之间不画线。
- ❌ 没有第二个 primary，没有无含义的颜色。
- ❌ `style.css` 里没有 `#hex`、不在刻度上的 `font-size`/`border-radius`/`gap`/`padding`、没有裸 cubic-bezier。
- ❌ TSX 的 `style={{}}` 只放几何与数据颜色（位置、尺寸、`--clip-color`），不放主题色。
- ❌ 不为“显得不模板化”加装饰。

## 对照检查

1. `pnpm lint:design`：机械的一半——原始颜色、刻度外字号/圆角/间距、裸 cubic-bezier、TSX 内联主题色。发现即 bug，用 token 或变体修，不要放宽阈值。
2. 判断的一半：按本页 1–8 节逐项走一遍目标屏幕（中文 1440×900 与 1280×800、英文），列出违反项与对应规则，修掉或在本页争论规则。方法与截图路径见 `docs/HANDOFF.md` 的“QA 自动化方法”。
