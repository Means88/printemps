# Printemps 配置建议与介绍页素材

记录日期：2026-09-19。用于后续介绍页，不是已验证的最低系统要求。

## 建议配置（工程建议，待实测）

| 场景 | 建议配置 | 备注 |
| --- | --- | --- |
| Windows / Linux 常规使用 | 现代 6 核 CPU、16 GB RAM、NVIDIA 8 GB 显存、SSD | 以 CUDA、逐个声部分离为目标 |
| 长音频、多声部频繁使用 | 32 GB RAM、12 GB 以上显存、SSD | 为推理、缓存及长音频留余量 |
| Apple Silicon Mac | M 系列、16 GB 统一内存起，建议 24–32 GB | MPS 加速需逐模型验证，尚不能承诺兼容性或速度 |
| 仅 CPU | 现代 4–8 核 CPU、16 GB RAM | 作为兼容模式目标；可用性、耗时仍需验证 |

主要计算负担来自声部分离。以上显存与内存数字是产品工程建议，不是模型作者公布或 Printemps 实测的最低门槛，不承诺实时分离。

## 已查证的来源数据

- BS-Roformer Mega v1：单个权重约 77.6 MB，53 个权重集合约 4.11 GB；按所选声部下载。权重文件大小不等于推理显存占用。
  来源：https://huggingface.co/noblebarkrr/BS-Roformer-MVSep-Mega-53-stems/tree/main/v1
- Beat This!：默认模型 final0 约 78 MB，轻量 small0 约 8.1 MB；官方推理支持 CUDA，并提供 CPU 回退。
  来源：https://github.com/CPJKU/beat_this#inference
  模型列表：https://github.com/CPJKU/beat_this#available-models
- Essentia KeyExtractor：传统调性分析算法，不需要额外神经网络权重；计划在 CPU 上运行。
  来源：https://essentia.upf.edu/reference/std_KeyExtractor.html

## 磁盘预算

建议先预留 10–20 GB，覆盖运行依赖、按需下载的模型、私有音频结果和临时文件。该空间预算仍需用正式安装包验证，不能当作完整项目容量上限。

估算：44.1 kHz、立体声、32-bit float PCM 每分钟约 21.17 MB（44100 × 2 × 4 × 60 字节，十进制 MB，不含容器开销）。当前开发实现使用该内部格式；容器额外开销很小。长音频、多声部、二次分离及导出副本会增加占用。

## 计划采用的默认运行策略

- 一次运行一个分离模型，采用较低推理批量。
- 分析和分离协调排队，避免争抢资源影响试听。
- 显存不足时降低受支持的推理负载，必要时提示切换设备；具体策略需实现与验证。
- 只有下载模型需要联网；分离、分析、试听和导出均在本地执行。

## 发布介绍页前补齐

1. 在 CPU、NVIDIA CUDA、Apple Silicon 上验证兼容性与性能。
2. 使用真实歌曲测量耗时、峰值内存/显存、临时磁盘占用，记录歌曲长度、目标声部数及推理参数。
3. 确认操作系统版本、架构、驱动要求及安装包大小。
4. 将实测最低配置、建议配置及未支持设备明确区分；公开性能数字需附测试条件。

当前开发实现已完成本机 CPU 的短合成音频分离与离线分析验证；尚未完成上述跨平台整机与真实歌曲性能测试。

## 分析组件内置与应用增量更新（2026-09-20）

优先将体积适合的分析工具与必要权重随应用内置，不要求用户单独下载分析组件。评估完整运行依赖、各平台安装包体积，不能仅按权重大小决定。声部分离模型仍按需下载缓存。

不做独立的分析组件版本管理产品功能；分析工具与应用统一发布、测试与升级。计划使用 electron-builder + electron-updater，优先差分下载（blockmap），在本地重建并校验完整更新包，再按平台安装流程更新。不是运行中热替换任意代码。

平台打包目标优先 Windows NSIS、macOS 签名应用及更新 ZIP、Linux AppImage；实际差分支持与效果须锁定工具版本后验证，不把所有 Linux 安装格式都视作同等支持。发布端保留对应发布文件与更新元数据、所需 blockmap，支持 HTTP Range 请求；客户端缺少旧包缓存或差分失败时允许回退全量下载，因此不能承诺每次都是增量。

保持大体积内置资源内容与布局稳定，避免不必要的重新生成与压缩变化；这有助于差分复用，但最终节省比例需实测。内置分析组件版本写入内部构建清单用于诊断，无需独立更新界面。项目数据、私有结果和已下载分离模型置于应用数据目录，应用升级不重新下载或覆盖它们。推理期间不强制安装更新，完成任务后再提示重启。

验证至少覆盖：仅界面改动、分析权重改动、Electron运行时升级、首次更新无缓存、跨版本更新、差分失败回退。记录各平台真实下载量后再用于介绍页。自动更新是额外联网场景；基本音频功能仍在本地完成。

参考：https://www.electron.build/docs/features/auto-update/
https://www.electron.build/docs/troubleshooting/

### 本机 MPS 验证补充

Torch 2.11.0 能识别当前 Mac 的 MPS，但真实鼓组模型测试在约四分钟内未完成首块处理。进程采样显示在 MPS 内存缓存回收过程中等待 Metal 命令完成，已主动终止；原因尚未确定，不能作为性能数据或兼容性通过依据。MPS 选项标为实验性，自动模式仍优先 CUDA，否则 CPU。

### 2026-09-20 打包实测补充

- 当前 NumPy 2.5.3 的 macOS arm64 wheel 标记为 `macosx_14_0_arm64`，因此应用打包下限调整为 macOS 14.0。构建前检查依赖 wheel 声明，避免安装包声明低于依赖要求；尚未在 macOS 14 真机完成整机验收。
- Linux x64 容器内，常规测试、真实 CPU 节拍/调性分析、AppImage 构建及包内分析通过。没有验证 Linux 图形界面、实际音频设备或 CUDA 显卡。
- 本次含 CUDA 运行库的 Linux AppImage 为 3,045,393,931 字节，约 3.05 GB；Python 运行时目录约 4.7 GiB。完整依赖体积远大于分析模型的 8.1 MiB，介绍页不能仅用权重大小描述下载和安装空间。该测试包不是正式发布包，后续体积可能改变。
- Python 依赖已生成带哈希的跨平台锁文件，并随应用统一构建。固定依赖有利于稳定重复构建及差分复用，但仍不承诺每次更新都只下载增量。

## Linux 实际包差分验证（2026-09-20）

本地 0.1.0→0.1.1 AppImage 使用 electron-updater 的真实嵌入 blockmap 差分下载器，经 localhost HTTP Range 请求重建。新包 3,045,394,056 字节，实际传输含元数据 4,042,905 字节，共 8 次请求，复用比例 99.867%，完整 SHA-512 校验通过。证据见 `.cache/linux-verification/delta-0.1.0-to-0.1.1.json`。这是本次小改动的实测，不可用于承诺所有更新比例；尚未覆盖安装器执行、发布服务器、跨平台升级和全量回退端到端验证。
