## 本地运行原则

本节是实现约束，不作为产品页面宣传文案；页面不强调无需账号、完全本地等信息。

**除用户触发的模型下载外，全部基本功能在本机完成。**

导入与解码、声部分离、波形生成、播放与混音试听、项目保存与恢复、导出及缓存管理都不依赖远端服务。无需账户，不上传音频，不接入云端推理、遥测、在线授权或远程字体。已有模型时，启动及处理不应发出网络请求。模型目录随应用提供静态清单，不在每次启动时在线刷新。

模型下载仅获取指定声部的权重与 YAML 配置；支持下载进度、取消和失败重试。缓存完整性校验通过后方可标为已缓存。已完成模型保留供下次使用，离线缺少模型时引导联网下载或只处理已缓存声部。

注意：Pen 自动导出的 HTML 含 Google Fonts 引用，仅用于设计参考。**不得直接将这些外部链接带入产品**；应用实现必须打包字体、图标、脚本及其他资源。设计总览使用本地 PNG，可直接离线打开。

## 核心交互

### 导入与分离

1. 只在前置导入页选择或拖入一个音频创建项目，不支持一次导入多个音频。工作台仅提供历史记录、试听和导出，不提供“导入音频”或“分离声部”按钮。支持 WAV、FLAC、MP3、M4A 是设计目标，解码支持需在 Electron 实现阶段验证。更换源文件创建新会话，避免混入旧结果。
2. 使用搜索、声部分类或组合预设选择目标。输入即时筛选，匹配中文名称、英文名称与类别，忽略英文大小写和首尾空白。关键词与分类取交集；支持清空搜索与无结果状态；筛选隐藏的已选声部仍保留在选择集合中。声部名称显示本地化标签，内部始终使用仓库的稳定标识。零选择时禁止开始分离。
3. 配置页展示选中数量、已缓存数量和实际待下载文件合计。示例为 5 个声部、3 个已缓存、2 个待下载，共约 155.2 MB。
4. 点击“开始分离”后：缺少模型则先下载，全部已缓存则直接在本机推理。53 个目标模型不是一次运行同时生成 53 个互斥音轨。
5. 完成的声部立即加入同步时间轴。取消剩余任务保留完成结果；失败只重试受影响声部。CPU 重试仅更改该次处理设备。

### 多轨试听

- 原始音频与分轨模式互斥，切换时保持播放位置，避免双重叠加。
- 全部轨道共用一个播放时钟、游标、时间缩放和循环范围；点击时间标尺定位；Space 播放/暂停；返回起点后停留在 00:00。
- S 为多选独奏，M 为静音。存在独奏时只播放未静音的独奏声部；静音优先。原始轨道仅在原始模式下参与试听。
- 轨道与总线音量仅影响试听，不改变保存的分离数据。
- 已选轨道用背景与边框区分；S/M 的激活状态同时依赖按钮文字和颜色。
- 1440 宽右侧展示当前音轨详情、结果文件与单轨导出；1280 宽默认收起详情。两种布局保留历史记录与导出，不在工作台重复提供导入或分离操作。
- 波形是声部内容的可视化示例，未使用真实音频或模型输出；不同模型可能有目标重叠，不能承诺所有声部相加精确还原原曲。

### 导出与保存

- WAV 或 FLAC，每个选择的声部生成单独文件，保持完整时长及时间对齐；不将试听音量、静音、独奏应用于文件。
- 示例规格为 24-bit / 44.1 kHz / Stereo。实际模型输出、源采样率转换与长度对齐须在实现阶段验证。
- 输出命名为 `<源名称>_<声部标识>.<扩展名>`；零轨道选择时禁用导出。
- 遇到同名文件时提示“自动编号 / 替换 / 取消”，默认自动编号；不要静默覆盖。
- 导出失败保留项目中的结果，可选择其他目录后重试。成功后提供“打开文件夹”和“返回工作台”。
- 最近项目、模型缓存路径、语言及输出目录均保存在本机。清理模型缓存不删除项目或音频结果。

### 历史工作记录

- 首页和工作台均可进入历史页；每条记录对应一次单音频分离任务，展示音频名称、源文件名、声部摘要、处理时间和完成状态。
- 搜索音频名称、源文件名及中英文声部名称，忽略大小写和首尾空白。搜索与状态筛选共同生效；默认按处理时间倒序，切换筛选回到第一页。
- 点击记录显示结果详情，“打开”恢复该记录的工作台，可继续试听与导出。部分完成记录只展示实际完成的结果；缺失文件标为不可用，不自动重新分离。
- 删除使用确认对话框，默认仅移除工作记录；“同时清理应用保存的试听结果”默认不选。始终保留原始音频和用户另行导出的文件。取消不产生变更，删除后刷新列表与结果数量。
- 无记录时提供“新建分离”；搜索无匹配时提供“清空搜索”，不误删或隐藏持久化记录。

### 组件实现约定

- Electron 前端采用 Radix UI Primitives 配合自定义暗色样式；使用 Radix Icons 对应图标，保持 Pen 设计的尺寸与视觉重量。Pen 当前 Lucide 图标作为视觉参考，不需额外引入第二套运行时图标库。
- 删除确认使用 AlertDialog；状态筛选与处理设备使用 Select；声部选择使用 Checkbox；轨道音量使用 Slider；独奏/静音使用 Toggle；图标按钮提供 Tooltip 和可访问名称。
- 搜索采用有标签的文本输入框和清空按钮；列表结果计数通过可访问状态区域公布。Tab 可操作、Enter 激活、Esc 清空搜索或关闭最上层对话框，对话框关闭后焦点返回触发按钮。
- 设计页、PNG 和静态导出不是可运行的 Radix 实现，依赖将在后续应用开发阶段接入。

### 状态与设置

覆盖下载中断、离线缺模型、磁盘空间不足、分离失败、导出目录不可写以及导出成功。提示说明已保留的内容，并提供明确恢复操作。

界面支持简体中文和英语。语言即时切换，不修改文件名或声部标识。处理设备下拉仅列出本机实际可用设备；默认自动选择，可显式使用 CPU，界面不保证尚未验证的 GPU 后端。

## 私有试听结果与导出边界

分离结果保存在应用私有数据目录，作为应用管理的试听资产。界面不提供结果路径、在文件管理器显示、拖出文件或用外部程序打开等入口。历史记录的“试听”恢复应用内工作台；“导出音轨”进入导出流程。

导出在用户选择的文件夹生成独立副本，不使用硬链接或符号链接。外部编辑或删除副本不会改变内部试听资产。“打开文件夹”仅在成功导出后指向导出目录。导出失败保留内部结果，可换目录重试。

内部结果以任务和声部标识管理；重新处理先写入临时资产，完成后切换结果版本，避免正在试听的文件被覆写。历史删除中的结果清理仅作用于应用管理资产，不删除原始文件和导出副本；如保留结果，资产仍需在应用内部索引中可追踪以便后续清理。

私有目录属于应用管理边界，不是防止设备所有者通过操作系统访问文件的安全隔离承诺。当前交付为设计与实现约束，尚未实现文件存储后端。

## 音轨音量推子优化

参考 Logic Pro 的轨道头横向音量滑块及 Ableton 的刻度、数值反馈。保持现有布局，凹槽为 112×6 px，填充使用声部色，推子帽为 8×16 px 圆角矩形；固定 0 dB 参考线位于行程约 79%。0 dB 与 −3 dB 显示不同推子位置。中文及英文紧凑工作台、组件库已同步。

## BPM 与调性分析（新增范围）

工作台工具栏的音乐分析摘要打开详情；未分析显示“分析 BPM 与调性”，点击启动。导入后的原始音频是唯一分析输入；分析不依赖声部分离完成，不改变速度、音高、波形位置或导出资产。时间标尺仍以秒为单位，暂不添加自动吸附、节拍器或拍号推断。摘要展示全曲代表 BPM、全曲估计调性，变速或调性不明确显示“待确认”。结果、进度、缓存状态均为设计示例。新增 19 号画板展示详情、工具及六种状态。

Beat This! 默认 final0，仓库标称约 78 MB；可选 small0 约 8.1 MB。只下载选用的一个，显示实际下载字节与缓存状态，取消和重试复用模型下载管理。两个规格是体积选择，不宣称未经本机测试的耗时。Beat This 输出 beats/downbeats 时间点，并不直接给出全曲 BPM。实现时从有效相邻拍点间隔求稳健代表速度，保留局部速度与变速标记；不足拍点或稳定性不够不强行输出值。不得把拍点输出当作已识别拍号。模型自动下载必须由应用的显式下载流程控制，缓存后使用固定本地 checkpoint。

Essentia KeyExtractor 从音频计算 key、scale、strength，采用传统 HPCP 算法，不需要额外神经网络权重；随应用部署本地分析依赖。strength 是算法匹配强度，不是校准后的准确概率，不能显示为百分比置信度。验证后再确定不确定性阈值。独立记录 BPM / key 的 pending、waiting-model、running、complete、uncertain、failed、cancelled；一个失败不清空另一个，取消不打断试听或分离。资源冲突时排队显示“等待分析”，不要伪造推理百分比。首次缺少模型需显示下载并分析按钮；离线可先做调性。

修正结果展开原位表单：BPM 数字输入、÷2、×2；调性主音及 major/minor 选择；保存 / 取消 / 恢复自动结果。BPM 限制为 20–400 的有限数值，最多一位小数，错误保留表单并提示；键盘 Enter 保存、Esc 取消，倍速超范围禁用。记录自动估计与手动覆盖值、分析器版本、模型标识及源音频指纹，恢复项目无需重复分析；重新分析不默默覆盖手动修正。历史搜索后进入项目可查看既有分析。

本阶段完成 Pen 与静态预览，未接入分析运行时。实现前验证三平台打包及 Essentia 的 AGPL-3.0 许可与项目发行方式，勿视作 MIT 依赖。Beat This 代码与权重为 MIT。

- 所有弹窗、卡片、通知条的操作按钮一律右对齐；同组只有一个 primary，且 primary 放在最右，secondary 在其左侧。画板 10 与 12（英文长文案）的六张恢复状态卡片已按此调整；工作区任务通知的“关闭 / 重试”与下载失败弹窗的“取消任务 / 重试下载”同样遵循。
- 导出弹窗（画板 08）新增“对齐”行：剪辑范围（只导剪辑本身）或项目时间轴（按 offset 在开头补空白）。顶栏“导出”打开“导出音轨”弹窗，列出可见音轨复选，格式与对齐选项相同。
